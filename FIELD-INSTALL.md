# Интеграция СТО с 1С

Полная инструкция с командами: [INTEGRATION.md](INTEGRATION.md).
Установка production runner и автообновление: [PRODUCTION-AUTODEPLOY.md](PRODUCTION-AUTODEPLOY.md).

## 1. Специалист 1С — до установки агента

Выполнить [блок специалиста 1С](one-c-extension-source/P-13-INTEGRATION.md).
Он включает доработку штатной печати, нативные профили, сборку `.cfe`, проверку на копии
и публикацию сервисов. Сейчас это **незавершённые работы**, а не готовые настройки.
До их завершения боевую запись не включать.

## 2. В кабинете СТО

1. Создать реальные СТО и склады.
2. Открыть интеграцию с 1С и получить код подключения агента.

## 3. На постоянно включённом Windows-компьютере СТО

Компьютер должен иметь доступ к боевой публикации 1С и `https://cto24.kz`.
Потребуются права администратора Windows, адрес публикации, логины и пароли чтения/обмена 1С.

Положить ZIP, его `.sha256` и `install-package.ps1` в `C:\Install`.
Открыть PowerShell **от имени администратора**:

```powershell
$zip = 'C:\Install\AvtoPult-OneCAgent-windows-x64.zip'
$hash = ((Get-Content "$zip.sha256" -Raw -Encoding UTF8).Trim() -split '\s+')[0]
$base = Read-Host 'Адрес публикации боевой 1С'
& 'C:\Install\install-package.ps1' -Archive $zip -ExpectedSha256 $hash -OneCBaseUrl $base
```

Ввести данные пользователей 1С и код подключения. API СТО: `https://cto24.kz/api/v1`.
Использовать ZIP и контрольную сумму из одного доверенного комплекта.
Для 1С по HTTP в доверенной локальной/VPN-сети добавить к команде `-AllowLocalHttp`;
передача учётных данных по такому соединению не шифруется самим HTTP.

Если файлы уже в `C:\one-c-agent`, но служба ещё не установлена:

```powershell
& 'C:\one-c-agent\setup-agent.ps1' -OneCBaseUrl $base
```

После исправления ошибки эту команду можно повторить: сохранённая конфигурация используется
повторно. Работающую службу не переустанавливать; для обновления использовать `update-service.ps1`.
Адрес `mkcopy` из предыдущих проверок — тестовый, не подставлять его в боевую настройку.

## 4. Выбрать справочники по названиям

```powershell
& 'C:\one-c-agent\configure-mappings.ps1'
```

Выбрать организацию, виды цен товаров/услуг/закупки, склад 1С для каждого склада СТО
и нормочасы услуги без норматива. Ввести `ДА` для сохранения. GUID копировать не нужно.
После записи мастер перечитывает результат из СТО. Отмена до подтверждения ничего не записывает.
Если API ответил `404`, сначала проверить версию развёрнутого API; не редактировать GUID вручную.

Этот шаг не создаёт нативные профили, клиентов и автомобили в 1С и не включает запись документов.

## 5. Проверить соединение

```powershell
& 'C:\one-c-agent\diagnose-agent.ps1' -NodeExe 'C:\one-c-agent\runtime\node.exe' -AgentDirectory 'C:\one-c-agent'
```

Проверить отсутствие ошибок и появление агента в кабинете СТО. `404` на
`/hs/avtopult/v1/diagnostics` исправляется в публикации **сервера 1С**, не сервера СТО.
Успешная диагностика соединения не подтверждает печать, проведение и обмен документами.

## 6. Включить боевую запись после нативной приёмки

Только после выполнения блока специалиста и согласования контрольного заказа:

1. На компьютере агента открыть от администратора
   `C:\ProgramData\AvtoPult\OneCAgent\agent-config.json`.
2. Изменить только строковое значение `ONE_C_ALLOW_WRITES` с `"0"` на `"1"`.
   Остальные поля и права доступа сохранить; содержимое файла никому не пересылать.
3. Выполнить `Restart-Service AvtoPultOneCAgent` и повторить диагностику из пункта 5.
4. Провести согласованный заказ: создание → изменение → счёт/PDF → оплата.
   Сверить документы, суммы и статусы в обеих системах.

При ошибке вернуть `ONE_C_ALLOW_WRITES` в `"0"`, перезапустить службу и передать журнал
без паролей. Не очищать локальную очередь и не удалять документы ради повторного запуска.
