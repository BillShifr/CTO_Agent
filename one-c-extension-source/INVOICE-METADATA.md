# Счета и PDF: реализованный слой, не подтвержденный в 1С

FR-INT-008. Модуль `AvtoPultСчета` — серверный, непривилегированный. Все входы требуют уже
открытой транзакции вызывающего кода; самостоятельно не фиксируют данные.

## Метаданные расширения

Непериодический независимый регистр `AvtoPultЗапросыСчетов`:

| Поле                          | Тип                                | Назначение                 |
| ----------------------------- | ---------------------------------- | -------------------------- |
| Заказ                         | ДокументСсылка.ЗаказКлиента        | Измерение                  |
| Попытка                       | Число(10,0), неотрицательное       | Измерение                  |
| Счет                          | ДокументСсылка.СчетНаОплатуКлиенту | Ресурс                     |
| СуммаТиын                     | Число(19,0), неотрицательное       | Ресурс                     |
| ИдентификаторЗапроса, EventId | Строка(128)                        | Ресурсы                    |
| SHA256                        | Строка(64)                         | Ресурс                     |
| Состояние                     | Строка(20)                         | `awaiting-print` / `ready` |

Заказ обязан иметь ровно одну запись `AvtoPultЗаказы` (описание — в метаданных модуля заказов).
Создание счета устанавливает в ней `СчетВыставлен = Истина`, блокируя изменение состава.
Блокировки: регистр заказов → документ заказа → попытка счета. Экспорт PDF: регистр заказов →
документ счета → попытка. Пока регистр заказов блокируется целиком: безопасно, но сериализует
выставление счетов; производительность нужно измерить на копии.

## Что делает код

- `Подготовить(Payload)` проверяет связь заказа, попытку и точное совпадение суммы. Создает
  **непроведенный** счет через штатное заполнение по заказу; сохраняет попытку и замораживает состав.
  Повтор возвращает тот же счет, другая сумма той же попытки отклоняется.
- `ПринятьPDF(Счет, Попытка, ТабличныйДокумент)` принимает форму только от доверенного серверного
  обработчика печати. Проверяет счет и сумму, экспортирует PDF, считает SHA-256, атомарно сохраняет
  бинарный outbox и `ready`. Повтор не генерирует другой PDF и не создает другое событие.
- HTTP-вход `Создать(Payload)` возвращает успех только для уже готовой попытки. Иначе — повторяемый
  `503 PRINT_PIPELINE_NOT_CONFIGURED`, **не ложный 202**. Этот ответ не должен кешироваться транспортом.

## Незакрытый участок

Штатная функция получения печатной формы конкретной КА2 пока не подтверждена. Ее имя не выдумано,
вызов не подменен тестовой формой. Нужно связать `Подготовить` → реальная печать → `ПринятьPDF`
в одной транзакции или реализовать проверенный восстанавливаемый обработчик очереди печати.
После этого HTTP-вход должен вызывать этот путь, а не требовать предварительно готовую попытку.
До подключения пути автоматическое выставление счета **не готово**.

На полной тестовой 1С обязательно проверить заполнение обязательных реквизитов/графика оплаты,
печать правильных банковских реквизитов и сумм, права, отсутствие дублей после потерянного ответа,
параллельные изменения, откат при ошибке PDF, доставку/повтор PDF и восстановление после перезапуска.
Метаданные OData подтверждают `ДокументОснование` счета и отсутствие в нем `Товары`, но не поведение
его `ОбработкаЗаполнения` и печати. Синтаксис/запись пока не исполнены в платформе.

Платформенный экспорт PDF использует временный файл с удалением при успехе/ошибке; внешнего пути
из запроса нет. Основания API: [PDF 8.3.23](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_8.3.23_Developer_Guide/Chapter_16._Operations_with_various_data_formats/16.4._PDF_format/16.4.3._Digital_signature/),
[временные файлы](https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_Development_Standards/Client_server_interaction/Accessing_file_system_programmatically/?language=en).
