# Платежи и возвраты — FR-PAY-007/008

Исходник использует только подтверждённые на копии документы и прямую ссылку строки
`РасшифровкаПлатежа` на `ДокументСсылка.ЗаказКлиента`. Пустой остаток регистра расчётов
не считается оплатой.

## Подписки

Одна серверная подписка `ПриЗаписи` вызывает
`AvtoPultРасчеты.ПриЗаписиРасчетногоДокумента(Источник, Отказ)` для:

- `ПриходныйКассовыйОрдер`, `ПоступлениеБезналичныхДенежныхСредств`,
  `ОперацияПоПлатежнойКарте`;
- `РасходныйКассовыйОрдер`, `СписаниеБезналичныхДенежныхСредств`.

Учитываются только операции `ПоступлениеОплатыОтКлиента`/`ВозвратОплатыКлиенту`.
Строка без однозначной связи с уже связанным заказом AvtoPult не экспортируется.

## Регистры

- `AvtoPultСостоянияРасчетов`: измерения `SourceKind`, `SourceId`, `AllocationKey`
  (строки 128); ресурсы `WorkOrderExternalId` (128), `Revision` (15,0), `Active`
  (булево), `AmountTiyn` (строка 19), `PrimaryEvent`, `InverseEvent` (строки 32).
- `AvtoPultИзмененияРасчетов`: измерение `EventId` (128); ресурсы `PayloadJSON`
  (неограниченная строка), `WorkOrderExternalId` (128), `State` (16), `CreatedAt` (дата UTC).

`SourceId + AllocationKey + Revision` образуют поколение распределения. Снятие проведения,
удаление строки или изменение суммы создаёт обратное событие старого поколения. Повторное
проведение создаёт новое поколение; старый `paymentExternalId` не переиспользуется.

## Обязательная приёмка на тестовой 1С

Частичная/полная оплата, две строки одного документа, снятие проведения, повторное проведение,
изменение суммы, удаление и возврат. Для каждого сценария проверить event ID, сумму, порядок,
повтор claim/ACK, обрыв связи и отсутствие двойного ledger effect в AvtoPult.
