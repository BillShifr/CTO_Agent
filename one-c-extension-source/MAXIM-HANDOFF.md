# Передача интеграции 1С Максиму

## Что уже готово

- Windows Agent устанавливается рядом с 1С и сам открывает только исходящие HTTPS-соединения с
  AvtoPult Cloud. Публичный IP, входящий порт и Radmin VPN для этого пути не нужны.
- Связь Agent → 1С идёт по `localhost` либо обычной LAN. Локальный HTTP разрешается только явным
  флагом и не должен выходить за доверенный хост/сеть.
- Реализованы OData, запись заказов, запрос счетов, payroll, локальный outbox событий/PDF,
  heartbeat, повторы, disk spool, один экземпляр службы и передача больших OData-коллекций
  проверяемыми частями.
- В пакете есть исходники каркаса расширения, Windows-скрипты установки и SHA-256 каждого файла.

## Что нельзя завершить без копии конкретной 1С

`AvtoPultАдаптерКА2` зависит от метаданных нетиповой базы и в репозитории отсутствует. До
production Максим должен на копии базы сопоставить и реализовать:

1. Заказ клиента, счёт, оплату и возврат, их организацию, валюту и соглашение.
2. Номенклатуру, услуги, виды цен и склады по реальным GUID.
3. Начисления зарплаты и допустимые состояния документов.
4. Постановку событий и PDF в `AvtoPultИсходящиеСобытия` в той же транзакции, что и реальный
   документ 1С.

Сигнатуры функций, два допустимых варианта ответа, разрешённые HTTP-коды и fail-closed поведение
описаны в `ADAPTER-CONTRACT.md`. Возвращать исключение для ожидаемой ошибки сопоставления или
версии нельзя: транспорт обоснованно трактует неожиданное исключение как временный внутренний
сбой. Ожидаемая ошибка возвращается структурой адаптера и сохраняется для точного replay.

Без этого `.cfe` собрать достоверно невозможно. Готовность каркаса или успешный mock не является
доказательством совместимости с базой заказчика.

## Данные для установки

Публичные параметры можно передать обычным рабочим сообщением:

- публичный `ApiUrl` AvtoPult с HTTPS;
- идентификатор агента и UUID подключения/СТО;
- локальные URL публикации 1С для `/hs/avtopult/v1/` и `/odata/standard.odata/`;
- GUID организации, подразделения, соглашения, валюты, видов цен и каждого склада;
- путь установки Node.js 22.20.x, WinSW 2.12.0 x64 и каталог агента.

Параметры передаются отдельно, а секреты — по согласованному защищённому каналу; они вводятся
интерактивно в `configure-environment.ps1`. Секреты нельзя добавлять в Git, тикет или
диагностический лог:

| Значение                                                         | Кто создаёт                 | Где используется                                                                              |
| ---------------------------------------------------------------- | --------------------------- | --------------------------------------------------------------------------------------------- |
| Agent secret, минимум 32 символа                                 | AvtoPult                    | Cloud `IntegrationConnection.secretRef` и локальный Agent                                     |
| Пароль пользователя записи 1С                                    | Максим/администратор 1С     | Только локальный HTTP-сервис с минимальными правами                                           |
| Пароль read-only пользователя OData                              | Максим/администратор 1С     | Только разрешённые OData-коллекции                                                            |
| Smart POS DNS, имя кассы, access/refresh token и callback secret | Владелец терминала/AvtoPult | Только если Smart POS реально подключён к этой LAN; IP терминала закрепить в DHCP или вручную |

Пароли записи и чтения должны принадлежать разным пользователям. Agent secret, callback secret и
пароли 1С должны быть разными значениями.

## Последовательность без production-риска

1. Сверить `SHA256SUMS`; работать только с пакетом, чей commit SHA сообщил владелец AvtoPult.
2. Собрать расширение в Конфигураторе и выполнить синтаксическую проверку.
3. Установить `.cfe` в копию базы; создать отдельных пользователей чтения и записи.
4. Пройти полностью `one-c-write-api.md`, включая одинаковый ключ, конфликт тела, два
   параллельных запроса, потерянный ответ, возврат, PDF и повтор `EventId`.
5. Настроить Agent через elevated PowerShell. Скрипт сам запросит секреты и сохранит их в файле,
   доступном только SYSTEM и Administrators.
6. Установить службу, перезагрузить Windows и повторить heartbeat, OData, запись, событие, PDF и
   восстановление очереди после искусственного обрыва сети.
7. Перед production сделать резервную копию, установить тот же проверенный `.cfe` и пакет Agent,
   выполнить один обезличенный тестовый заказ и зафиксировать фактические идентификаторы/время.

Production включается только после успешных шагов 1–6 на копии. Остановка Windows-службы
останавливает новые задания и является штатным способом немедленно прекратить обмен.
