# Контракт `AvtoPultАдаптерКА2`

Этот серверный общий модуль является единственной частью расширения, зависящей от метаданных
конкретной базы «Комплексная автоматизация для Казахстана». Его нельзя заменить догадками по
типовой конфигурации: имена дополнительных реквизитов, правила контрагентов, складов, документов
и зарплаты подтверждаются на копии фактической базы.

Модуль предоставляет четыре экспортные функции:

- `SHA256(Текст)` возвращает SHA-256 точных UTF-8 байтов строки как 64 строчных hex-символа;
- `ПрименитьЗаказКлиента(Payload)` проверяет и применяет `oneCWorkOrderUpsertRequestSchema`;
- `СоздатьИлиНайтиСчет(Payload)` проверяет и применяет `oneCInvoiceRequestSchema`;
- `ПрименитьНачисления(Payload)` проверяет и применяет `oneCPayrollExportRequestSchema`.

Три бизнес-функции возвращают один из двух строгих вариантов.

Успех:

```bsl
Возврат Новый Структура("Успех,Данные", Истина, РезультатКонтракта);
```

`РезультатКонтракта` обязан соответствовать схеме конкретной операции. Для запроса счёта
транспорт вернёт и сохранит HTTP 202; для остальных операций — HTTP 200.

Контролируемая бизнес-ошибка:

```bsl
Возврат Новый Структура(
    "Успех,КодHTTP,Код,Сообщение,Повторяемая",
    Ложь,
    409,
    "STALE_VERSION",
    "Версия заказ-наряда устарела",
    Ложь);
```

Для `STALE_VERSION` структура дополнительно содержит числовое неотрицательное целое поле
`ТекущаяВерсия`; транспорт отдаёт его в JSON как `currentVersion`.

Для терминальных ошибок разрешены только 400, 403, 404, 409 и 422. Для временных ошибок с
`Повторяемая = Истина` разрешены только 423, 429, 502, 503 и 504. Код ограничен 3–64 символами,
сообщение — 1–500 символами и не должно содержать персональные данные, SQL, пути, credentials
или текст внутреннего исключения. Неполный либо недопустимый ответ адаптера fail-closed
превращается транспортом в фиксированный `500 ONE_C_APPLICATION_ERROR`.

Успех и контролируемая ошибка сохраняются в `AvtoPultИдемпотентность` в той же транзакции, что и
бизнес-вызов. Повтор одинакового `Idempotency-Key` и тела получает точный сохранённый HTTP-код и
тело; другой payload с тем же ключом получает `409 IDEMPOTENCY_CONFLICT` до бизнес-вызова.

Функция заказа обязана реализовать детерминированное сопоставление клиента, автомобиля,
номенклатуры и склада, version/stale guards и стабильную внешнюю ссылку. Функция счёта обязана
использовать `(workOrderExternalId, requestAttempt)` как уникальную попытку и поставить результат
печати либо ошибку в локальный outbox. Функция зарплаты обязана использовать `periodId` как
устойчивую внешнюю идентичность. Создание исходящих событий и PDF выполняется через
`AvtoPultИнтеграция` внутри той же транзакции, что и соответствующий документ 1С.

Готовность этого модуля доказывается только синтаксической проверкой Конфигуратора, сборкой `.cfe`
и полной матрицей из `one-c-write-api.md` на копии базы. Наличие файла с этими сигнатурами без
проверенных обращений к реальным метаданным не считается реализацией.
