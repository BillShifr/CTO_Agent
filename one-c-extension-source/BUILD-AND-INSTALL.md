# Сборка и установка расширения

Скрипты работают только с отдельной служебной/тестовой базой. Production ими не обновляется.

## Однократная подготовка проекта

1. В Конфигураторе платформы `8.3.23.2040` создать расширение `AvtoPult`.
2. Создать объекты из `extension-project-manifest.json` и описаний `*-METADATA.md`.
3. Выгрузить расширение в иерархические XML-файлы. В корне должен появиться
   `Configuration.xml`.

Репозиторий намеренно не генерирует эти XML вручную: внутренние UUID и формат должен создать
Конфигуратор. Неполный проект отклоняется до изменения базы.

## Сборка `.cfe`

Учётные данные задаются только в текущей PowerShell-сессии:

```powershell
$env:AVTOPULT_1C_USER = 'integration-build-user'
$env:AVTOPULT_1C_PASSWORD = Read-Host '1C password'

.\tools\Build-Extension.ps1 `
  -PlatformExe 'C:\Program Files\1cv8\8.3.23.2040\bin\1cv8.exe' `
  -InfoBase 'server\service_test' `
  -ExportedProject 'C:\AvtoPult\extension-project' `
  -OutputCfe 'C:\AvtoPult\artifacts\AvtoPult.cfe' `
  -EnvironmentAcknowledgement I-CONFIRM-NON-PRODUCTION-BUILD-INFOBASE
```

Скрипт проверяет полный состав проекта, заменяет модули версиями из `src`, выполняет загрузку,
проверку модулей, конфигурации и применимости, затем создаёт `.cfe`, логи и `.sha256`.

## Установка в тестовую базу

```powershell
.\tools\Install-TestExtension.ps1 `
  -PlatformExe 'C:\Program Files\1cv8\8.3.23.2040\bin\1cv8.exe' `
  -InfoBase 'server\service_test' `
  -Cfe 'C:\AvtoPult\artifacts\AvtoPult.cfe' `
  -EnvironmentAcknowledgement I-CONFIRM-TEST-INFOBASE
```

Установка проверяет SHA-256, загружает расширение, обновляет конфигурацию тестовой базы и
повторно запускает проверки применимости, модулей и конфигурации. После этого вручную запускаются
`AvtoPultСамопроверка.ПроверитьУстановку()` и `AvtoPultСамопроверка.ПроверитьКонтракт()`.

## Определение регистров движений

Для каждого заранее выбранного проведённого тестового документа выполнить на сервере 1С:

```bsl
Результат = AvtoPultДиагностикаКА2.НайтиРегистрыДвижений(СсылкаДокумента);
Профиль = AvtoPultДиагностикаКА2.СформироватьПрофильДвижений(СсылкаДокумента);
```

Профиль принимается только если `Результат.Успех = Истина`; при непустом `Ошибки` результат
нельзя использовать. Список `Регистры` фиксируется отдельно для каждого из семи типов документа
и затем передаётся в `AvtoPultПроведение.ПровестиИПроверить`. `Профиль` содержит каноническое
имя типа документа, отсортированные регистры и SHA-256; эти три значения сохраняются вместе,
чтобы исключить подмену или применение профиля другого документа.

## Проверка полного rollback

Только на специально созданном **непроведённом** документе тестовой базы и после подтверждения
профиля движений выполнить:

```bsl
Результат = AvtoPultНативнаяПриемка.ПроверитьОткатПроведения(
	СсылкаДокумента,
	ПодтвержденныеРегистры);
```

Проверка дважды проводит документ внутри отдельной транзакции: сначала штатно, затем с
искусственной ошибкой после проверки реальных движений. Обе транзакции отменяются. Успех
возвращается только если документ остался непроведённым и во всех регистрах накопления нет
остаточных движений. Функция запрещает запуск внутри внешней транзакции и не содержит
`ЗафиксироватьТранзакцию()`.

## Что требует тестовой КА2

- выбрать штатную команду печати счёта и подтвердить тип возвращаемой печатной формы;
- получить профили движений на реальных документах;
- доказать проведение и rollback на ошибке;
- выполнить полный цикл, повтор, обрыв связи, потерянный ответ и перезапуск агента.
