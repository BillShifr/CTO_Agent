# AvtoPult — серверное расширение 1С

Целевая база: «Комплексная автоматизация для Казахстана 2.4.5.21», платформа 8.3.23.2040.
Пакет исходников предназначен для расширения, публикующего только
`/hs/avtopult/v1/work-orders`, `/hs/avtopult/v1/invoices`,
`/hs/avtopult/v1/payroll-periods` и локальный outbox для Windows Agent
без изменения конфигурации поставщика.
Полный wire-контракт и матрица приёмки находятся в
`docs/runbooks/one-c-write-api.md`.

Это не готовый `.cfe`. В исходниках добавлены адаптер, проверка контракта, запись черновика
заказа, внутренние операции счета/PDF и самопроверка. Компиляция, установка и выполнение
на тестовой 1С пока не подтверждены. Загружать пакет в production до приёмки запрещено.

| Участок            | Реализовано в исходниках                                                                                     | Осталось                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Заказы             | Запись/изменение непроведённого документа, версии, блокировки, стабильные строки, проверка сумм после записи | Проведение, НДС, остальные статусы, создание клиентов/автомобилей                |
| Счета/PDF          | Внутренняя подготовка документа, стабильная попытка, бинарный outbox и SHA-256                               | Подключение штатной печати КА2; HTTP до этого возвращает 503, не фиктивный успех |
| Обратные изменения | Журнал, последовательный pump/ACK, baseline, блокировка конфликтов и подавление cloud-эха                    | Установка подписки и нативная приёмка                                            |
| Платежи/возвраты   | Нативный журнал поколений распределений, компенсации отмены/перепроведения и outbox/ACK                      | Установка пяти подписок и нативная приёмка                                       |
| Проведение         | Транзакционная запись, проверка движений, подписанный профиль и rollback-harness без commit                  | Получить профили на копии и выполнить нативную приёмку                           |
| Начисления         | Явный отказ без записи                                                                                       | Подтверждённое сопоставление зарплатного документа                               |

Точные метаданные новых регистров и ограничения: [заказы](ORDER-METADATA.md),
[счета](INVOICE-METADATA.md), [журнал обратных изменений](REVERSE-METADATA.md),
[платежи и возвраты](PAYMENT-METADATA.md). Серверные общие модули создаются непривилегированными,
с доступом только для выделенной роли интеграции. Каталог `AvtoPultIntegration` соответствует
имени модуля **`AvtoPultИнтеграция`** в конфигурации; остальные имена совпадают с каталогами.

Точный интерфейс адаптера, допустимые успешные ответы и бизнес-ошибки зафиксированы
в `ADAPTER-CONTRACT.md`. Транспорт отклоняет неполный ответ адаптера, сохраняет точный HTTP-код и
тело успешного результата либо терминальной ошибки в ledger; временные ошибки не кеширует.
Любая ошибка откатывает бизнес-записи. Транспорт возвращает `202` для запроса счёта и требует версию контракта на всех
локальных маршрутах. PDF выдаётся с `Cache-Control: private, no-store`.

## Метаданные расширения

- HTTP-сервис `AvtoPult`, корневой URL `avtopult/v1`;
- шаблон URL `work-orders`, метод `POST`, обработчик `WorkOrdersPOST`;
- шаблон URL `invoices`, метод `POST`, обработчик `InvoicesPOST`;
- шаблон URL `payroll-periods`, метод `POST`, обработчик `PayrollPeriodsPOST`;
- шаблоны `events/claim`, `events/<eventId>/ack`, `invoice-documents/claim`,
  `invoice-documents/<eventId>/content` и `invoice-documents/<eventId>/ack`; они доступны
  только учётной записи агента на localhost/LAN;
- регистр сведений `AvtoPultИдемпотентность`: ключ, операция, SHA-256 тела, код ответа, тело
  ответа, момент завершения;
- регистр сведений `AvtoPultЗаказы`: UUID AvtoPult, ссылка на `ЗаказКлиента`, версия AvtoPult,
  SHA-256 канонического payload, внешний version token;
- регистр сведений `AvtoPultЗапросыСчетов`: заказ, номер попытки, ссылка на счёт, статус;
- независимый регистр сведений `AvtoPultИсходящиеСобытия` с измерениями `EventId` (строка 128)
  и `Вид` (строка 32); ресурсы: `PayloadJSON` (неограниченная строка), `Содержимое`
  (`ХранилищеЗначения`), `Состояние` (строка 16), `LeaseToken` (строка 64), `LeaseUntil`
  (дата), `ЧислоПопыток` (число 10, 0), `СозданоВ` (дата), `ДоставленоВ` (дата),
  `КлючЗаказа` (строка 128), `Порядок` (число 18, 0),
  `РезультатВерсияЗаказа` (число 16, 0; 0 = результат неизвестен). Для `workorder.changed`
  ACK обязан содержать `workOrderVersion` из сохранённого ответа облака; версия и `delivered`
  записываются одной транзакцией. Не вычислять версию из текущего заказа. `EventId`
  неизменяем; разрешённые виды — `event` и `invoice-document`, состояния — `new`, `leased`,
  `delivered`;
- Порядок назначается при вставке под общей блокировкой очереди и не меняется при claim/ACK.
  По каждому заказу и виду выдаётся только первое недоставленное событие, включая истёкший
  lease; действующий lease блокирует следующие события заказа. PDF и callback — разные
  очереди: нельзя блокировать PDF ожиданием callback, которому нужен этот PDF.
  Подробности обновления и приёмки: [OUTBOX-ORDERING.md](OUTBOX-ORDERING.md).
- константы/настройки расширения для организации, подразделения, соглашения, вида цены, валюты,
  склада и callback URL/secretRef.

Идемпотентная запись и бизнес-эффект выполняются в одной транзакции 1С. Номер документа не
используется как идентификатор. Сопоставление номенклатуры и склада выполняется только по GUID.
Расширение не создаёт второй независимый складской резерв: оперативным резервом владеет
AvtoPult, а 1С отражает строки заказа и бухгалтерский остаток.

`npm run test:one-c-extension` включён в CI и `make verify`. Это проверка структуры исходников,
не замена синтаксической проверке и выполнению транзакционных сценариев на платформе 1С.
Команда `npm run verify:one-c-metadata -- /path/to/metadata-current.xml` сверяет выгруженную
OData-схему с базовыми объектами и полями, которые использует адаптер; записи 1С она не читает.
Зафиксированный результат для доступной тестовой базы находится в
[BASE-METADATA-VERIFICATION.md](BASE-METADATA-VERIFICATION.md).
После проверки синтаксиса на тестовой выполнить серверный вызов
`AvtoPultСамопроверка.ПроверитьУстановку()`, затем
`AvtoPultСамопроверка.ПроверитьКонтракт()`: первый проверяет наличие всех модулей, HTTP-сервиса,
регистров и полей расширения, второй — суммы/округление, валидацию заказа, JSON и SHA-256.
Оба вызова не создают бизнес-документы. Их успех не заменяет сквозную приёмку.
Профили реальных движений и полный откат проверяются отдельными вызовами из
[BUILD-AND-INSTALL.md](BUILD-AND-INSTALL.md); rollback-harness никогда не фиксирует транзакцию.

Перед чтением регистра идемпотентности обработчик берёт исключительную блокировку по ключу и
повторно проверяет сохранённый результат внутри той же транзакции. Поэтому два параллельных
запроса с одним ключом не могут оба вызвать бизнес-операцию; повтор с другой операцией или телом
получает 409, а длина ключа ограничена тем же wire-контрактом, что и облачный клиент.
Создание исходящего события также блокирует очередь до проверки `EventId` и записи. HTTP 500
возвращает только фиксированный код и сообщение: текст внутреннего исключения 1С наружу не
передаётся. Отсутствующие заголовки обрабатываются как контролируемая ошибка, а некорректный JSON
отклоняется до начала бизнес-транзакции.

Каждое изменение, которое должно попасть в AvtoPult (смена заказа, поступление/возврат
наличных или безнала), сначала записывается в неизменяемый предметный журнал в той же
транзакции 1С, что и бизнес-документ. Перед claim локальный pump под общей блокировкой переносит
его в `AvtoPultИсходящиеСобытия`. Агент забирает только leased-запись, отправляет её
в Cloud по исходящему HTTPS и подтверждает `ack` после ответа Cloud с тем же `eventId`. При
обрыве связи запись остаётся, lease истекает и агент повторяет доставку. Для PDF счёта агент
сверяет SHA-256 до отправки. Этот outbox обязателен: прямой callback из 1С в Cloud и внешний VPN в
боевом потоке не используются.

Прямое создание outbox остаётся для событий/PDF, которые уже имеют стабильный `EventId`.
Подписки заказов и расчётов не берут глобальную блокировку outbox внутри записи документа:
это исключает обратный порядок блокировок с ACK. Повторный `EventId` отклоняется: при повторной
доставке используется та же запись, а новая запись с тем же идентификатором не создаётся.
Оба пути требуют активной транзакции и совпадения `eventId` в теле и ключе очереди;
нарушение отклоняется до блокировок/записи, отдельная транзакция для события не создаётся.

## Сборка и установка

Манифест полного состава, проверка выгрузки, наложение исходников, проверки Конфигуратора,
сборка `.cfe`, SHA-256 и установка в тестовую базу автоматизированы. Команды и ограничения:
[BUILD-AND-INSTALL.md](BUILD-AND-INSTALL.md). До создания Конфигуратором настоящего
`Configuration.xml` сборка специально завершается ошибкой.

В репозитории не хранятся `.cfe`, пароли, VPN-адреса и реальные GUID/персональные данные.
