# AvtoPult — серверное расширение 1С

Целевая база: «Комплексная автоматизация для Казахстана 2.4.5.21», платформа 8.3.23.2040.
Пакет исходников предназначен для расширения, публикующего только
`/hs/avtopult/v1/work-orders`, `/hs/avtopult/v1/invoices`,
`/hs/avtopult/v1/payroll-periods` и локальный outbox для Windows Agent
без изменения конфигурации поставщика.
Полный wire-контракт и матрица приёмки находятся в
`docs/runbooks/one-c-write-api.md`.

Это не готовый `.cfe`: общий модуль `AvtoPultАдаптерКА2` зависит от фактических метаданных
нетиповой базы и должен быть реализован и проверен специалистом 1С в Конфигураторе. На доступном
RDP-сервере платформа/Конфигуратор 8.3.23.2040 отсутствуют, поэтому синтаксическая проверка,
сборка и установка пока технически невозможны. Загружать этот исходный каркас в production без
выполнения матрицы приёмки запрещено.

Точный интерфейс отсутствующего модуля, допустимые успешные ответы и бизнес-ошибки зафиксированы
в `ADAPTER-CONTRACT.md`. Транспорт отклоняет неполный ответ адаптера, сохраняет точный HTTP-код и
тело в идемпотентном ledger, возвращает `202` для запроса счёта и требует версию контракта на всех
локальных маршрутах. PDF выдаётся с `Cache-Control: private, no-store`.

## Метаданные расширения

- HTTP-сервис `AvtoPult`, корневой URL `avtopult/v1`;
- шаблон URL `work-orders`, метод `POST`, обработчик `WorkOrdersPOST`;
- шаблон URL `invoices`, метод `POST`, обработчик `InvoicesPOST`;
- шаблон URL `payroll-periods`, метод `POST`, обработчик `PayrollPeriodsPOST`;
- шаблоны `events/claim`, `events/<eventId>/ack`, `invoice-documents/claim`,
  `invoice-documents/<eventId>/content` и `invoice-documents/<eventId>/ack`; они доступны
  только учётной записи агента на localhost/LAN;
- регистр сведений `AvtoPultИдемпотентность`: ключ, операция, SHA-256 тела, код ответа, тело
  ответа, момент завершения;
- регистр сведений `AvtoPultЗаказы`: UUID AvtoPult, ссылка на `ЗаказКлиента`, версия AvtoPult,
  SHA-256 канонического payload, внешний version token;
- регистр сведений `AvtoPultЗапросыСчетов`: заказ, номер попытки, ссылка на счёт, статус;
- независимый регистр сведений `AvtoPultИсходящиеСобытия` с измерениями `EventId` (строка 128)
  и `Вид` (строка 32); ресурсы: `PayloadJSON` (неограниченная строка), `Содержимое`
  (`ХранилищеЗначения`), `Состояние` (строка 16), `LeaseToken` (строка 64), `LeaseUntil`
  (дата), `ЧислоПопыток` (число 10, 0), `СозданоВ` (дата), `ДоставленоВ` (дата). `EventId`
  неизменяем; разрешённые виды — `event` и `invoice-document`, состояния — `new`, `leased`,
  `delivered`;
- константы/настройки расширения для организации, подразделения, соглашения, вида цены, валюты,
  склада и callback URL/secretRef.

Идемпотентная запись и бизнес-эффект выполняются в одной транзакции 1С. Номер документа не
используется как идентификатор. Сопоставление номенклатуры и склада выполняется только по GUID.
Расширение не создаёт второй независимый складской резерв: оперативным резервом владеет
AvtoPult, а 1С отражает строки заказа и бухгалтерский остаток.

Перед чтением регистра идемпотентности обработчик берёт исключительную блокировку по ключу и
повторно проверяет сохранённый результат внутри той же транзакции. Поэтому два параллельных
запроса с одним ключом не могут оба вызвать бизнес-операцию; повтор с другой операцией или телом
получает 409, а длина ключа ограничена тем же wire-контрактом, что и облачный клиент.
Создание исходящего события также блокирует очередь до проверки `EventId` и записи. HTTP 500
возвращает только фиксированный код и сообщение: текст внутреннего исключения 1С наружу не
передаётся. Отсутствующие заголовки обрабатываются как контролируемая ошибка, а некорректный JSON
отклоняется до начала бизнес-транзакции.

Каждое изменение, которое должно попасть в AvtoPult (смена заказа, выставление счёта,
поступление/возврат наличных или безнала), сначала записывается в `AvtoPultИсходящиеСобытия` в
той же транзакции 1С, что и бизнес-документ. Агент забирает только leased-запись, отправляет её
в Cloud по исходящему HTTPS и подтверждает `ack` после ответа Cloud с тем же `eventId`. При
обрыве связи запись остаётся, lease истекает и агент повторяет доставку. Для PDF счёта агент
сверяет SHA-256 до отправки. Этот outbox обязателен: прямой callback из 1С в Cloud и внешний VPN в
боевом потоке не используются.

Код, проводящий бизнес-документ 1С, в той же транзакции вызывает
`AvtoPultИнтеграция.ПоставитьСобытиеВОчердь(...)` либо
`AvtoPultИнтеграция.ПоставитьPDFСчетаВОчердь(...)`. Повторный `EventId` отклоняется: при повторной
доставке используется та же запись, а новая запись с тем же идентификатором не создаётся.

## Сборка и установка

1. Установить клиент/Конфигуратор платформы 8.3.23.2040 на административной Windows-машине.
2. Создать расширение с перечисленными метаданными и поместить модули из `src/` в одноимённые
   объекты.
3. Проверить синтаксис, выгрузить `.cfe`, подписать хеш артефакта и загрузить сначала в копию.
4. В публикации базы включить HTTP-сервисы расширений (`publishExtensionsByDefault`).
5. Создать отдельного пользователя интеграции с минимальными правами и непустым паролем.
6. Пройти все пункты acceptance из runbook; только после этого повторить отдельный production
   smoke-test с обезличенным тестовым заказом.

В репозитории не хранятся `.cfe`, пароли, VPN-адреса и реальные GUID/персональные данные.
