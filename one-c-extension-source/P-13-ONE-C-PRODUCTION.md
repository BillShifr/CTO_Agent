# Подключение боевой 1С к СТО — действия специалиста 1С

**КА2** — «1С:Комплексная автоматизация для Казахстана, редакция 2». В этой инструкции речь
идёт о конфигурации версии `2.4.5.21` на платформе `1С:Предприятие 8.3.23.2040`.

## 1. Распаковать комплект

Скопировать `СТО-1С-production-kit.zip` на сервер 1С и выполнить PowerShell от имени
администратора:

```powershell
$kit = 'C:\СТО-1С-production-kit.zip'
$package = 'C:\AvtoPult\package'
$agent = 'C:\AvtoPult\agent'

Expand-Archive -LiteralPath $kit -DestinationPath $package -Force
$archive = Join-Path $package 'AvtoPult-OneCAgent-windows-x64.zip'
$expected = ((Get-Content "$archive.sha256" -Raw).Trim() -split '\s+')[0]
$actual = (Get-FileHash $archive -Algorithm SHA256).Hash
if ($actual -ne $expected) { throw 'Повреждён пакет агента' }
Expand-Archive -LiteralPath $archive -DestinationPath $agent -Force
```

Исходники расширения находятся в `C:\AvtoPult\agent\one-c-extension-source`. Готового `.cfe`
в комплекте нет: внутренние UUID проекта должен однократно создать Конфигуратор целевой КА2.

## 2. Подготовить копию базы для сборки

1. На сервере 1С создать копию боевой базы. Не выполнять сборку в боевой базе.
2. Установить клиент и Конфигуратор платформы `8.3.23.2040`.
3. Проверить путь платформы в PowerShell:

```powershell
$platform = Get-ChildItem 'C:\Program Files\1cv8' -Recurse -Filter 1cv8.exe |
    Where-Object FullName -Like '*8.3.23.2040*' |
    Select-Object -First 1 -ExpandProperty FullName
if (-not $platform) { throw 'Не найдена платформа 1С 8.3.23.2040' }
$platform
```

4. Записать строку подключения к копии в формате `сервер1С\имяБазы`.

## 3. Однократно создать проект расширения

Это единственный ручной этап. Конфигуратор выполняет его один раз, чтобы создать корректные
внутренние UUID и типизированные ссылки объектов КА2. После выгрузки XML-проект хранится вместе
с исходниками; при следующих обновлениях этот раздел не повторяется — `.cfe` собирается скриптом
из раздела 4.

1. Открыть копию базы в Конфигураторе.

## 4. Собрать и проверить `.cfe`

```powershell
$env:Path = "C:\AvtoPult\agent\runtime;$env:Path"
$output = 'C:\AvtoPult\artifacts\AvtoPult.cfe'
& "$root\tools\Build-Extension.ps1" `
    -PlatformExe $platform `
    -InfoBase $buildBase `
    -ExportedProject $project `
    -OutputCfe $output `
    -UserName $credential.UserName `
    -Password $credential.GetNetworkCredential().Password `
    -EnvironmentAcknowledgement I-CONFIRM-NON-PRODUCTION-BUILD-INFOBASE
if ($LASTEXITCODE -ne 0) { throw 'Сборка AvtoPult.cfe не выполнена' }
```

Скрипт сам проверит состав проекта, заменит модули актуальными исходниками, выполнит
проверку модулей, конфигурации и применимости. Результат:

- `C:\AvtoPult\artifacts\AvtoPult.cfe`;
- `C:\AvtoPult\artifacts\AvtoPult.cfe.sha256`;
- логи в `C:\AvtoPult\artifacts\logs`.

Установить файл в копию и повторно проверить его:

```powershell
& "$root\tools\Install-TestExtension.ps1" `

if ($LASTEXITCODE -ne 0) { throw 'Тестовая установка не выполнена' }
Remove-Variable credential
```

## 5. Проверить расширение на копии

В консоли серверного кода копии выполнить:

```bsl
AvtoPultСамопроверка.ПроверитьУстановку();
AvtoPultСамопроверка.ПроверитьКонтракт();
```

Оба вызова должны завершиться без исключения.

До дальнейшей приёмки нужно открыть модуль менеджера
`СчетНаОплатуКлиенту`, определить штатную серверную команду формирования печатной формы счета и
подключить её к цепочке `AvtoPultСчета.Подготовить` → печать → `AvtoPultСчета.ПринятьPDF`.
Пока вызов не подключён и не проверен, запрос счета возвращает
`503 PRINT_PIPELINE_NOT_CONFIGURED`; устанавливать такое расширение в боевую базу нельзя.

## 6. Создать тестовые профили одной командой

Для каждой станции выбрать заказ с нужными организацией, подразделением, соглашением, валютой,
складом, видом цены и правилами расчётов. Выбрать строку услуги без НДС. Для каждого сценария
проведения выбрать существующий проведённый документ нужного вида и операции.

```bsl
JSONНастроек = "{""stations"":[{""stationId"":""STATION-ID"",""orderNumber"":""ORDER-NUMBER"",""year"":2026,""lineNumber"":1}],""postingProfiles"":[{""profileId"":""cash-receipt-v1"",""documentType"":""ПриходныйКассовыйОрдер"",""documentNumber"":""CASH-DOCUMENT-NUMBER"",""year"":2026}]}";
Результат = AvtoPultНастройкаПрофилей.НастроитьПрофилиИзJSON(JSONНастроек);
```

Функция находит документы по номеру и году, создаёт технические образцы и профили, а также
определяет регистры движений. GUID и ручное заполнение регистров не нужны. Повтор безопасен:
готовые записи вернут `replayed`, отличающиеся настройки будут отклонены.

Открыть возвращённые `template`, проверить реквизиты и отсутствие проведения. После успешной нативной
приёмки в `AvtoPultПрофилиСтанций` включить `Проверен` и, только для проверенного сценария без НДС,
`БезНДСПодтверждено`; в `AvtoPultПрофилиПроведения` включить `Проверен` и заполнить `ПроверенВ`.

## 7. Провести нативную приёмку на копии

1. Создать профиль станции и повторить команду — один шаблон и один профиль.
2. Повторить с другим исходным заказом — конфликт без изменения профиля.
3. Создать профиль проведения и повторить — один профиль без дубля.
4. Заказ → изменение состава → проведение → проверить реальные движения.
5. Счёт → штатный PDF → проверить номер, сумму и содержимое.
6. Частичная оплата → полная оплата → отмена → перепроведение без двойного учёта.
7. Возврат → повтор команды → один возврат и правильный итог.
8. Вызвать ошибку проведения — документ, движения, очередь и PDF полностью откатываются.
9. Оборвать связь после выполнения команды — повтор не создаёт документ или движение заново.

Сохранить протокол: версия платформы, КА2 и расширения, SHA-256 `.cfe`, дата, база,
номера документов и результат каждого пункта.

## 8. Установить проверенный `.cfe` в боевую базу

1. Сделать резервную копию боевой базы и настроек веб-публикации.
2. Сверить SHA-256 файла с `AvtoPult.cfe.sha256` и протоколом приёмки.
3. Открыть «НСИ и администрирование → Печатные формы, отчёты и обработки → Расширения».
4. Нажать «Добавить из файла» и выбрать `C:\AvtoPult\artifacts\AvtoPult.cfe`.
   Для обновления использовать «Обновить из файла».
5. Перезапустить сеанс.
6. Повторить `ПроверитьУстановку()` и `ПроверитьКонтракт()` уже в боевой базе.

## 9. Создать профили в боевой базе

Повторить команду из раздела 6 с документами боевой базы и боевыми `StationId`.
Не переносить ссылки и GUID из копии. Проверить созданные шаблоны и движения, затем включить
флаги `Проверен`, `БезНДСПодтверждено` и заполнить `ПроверенВ`.

## 10. Заполнить связи в боевой базе

- `AvtoPultКлиенты`: идентификатор клиента СТО → партнёр и контрагент 1С.
- `AvtoPultАвтомобили`: идентификатор автомобиля СТО → автомобиль 1С.
- Проверить кассу, банковский счёт, валюту, соглашение, склад, налогообложение и печатную
  форму счёта.

## 11. Включить боевой веб-обмен

1. В Конфигураторе открыть «Администрирование → Публикация на веб-сервере».
2. Открыть существующую боевую публикацию, включить OData и HTTP-сервис `AvtoPult`.
3. Сохранить публикацию, не меняя её адрес и остальные сервисы.
4. Создать пользователя чтения справочников и пользователя записи с правами расширения.
5. Проверить, что оба адреса отвечают без `404`:

```text
GET <адрес-публикации>/odata/standard.odata/
GET <адрес-публикации>/hs/avtopult/v1/diagnostics
```
