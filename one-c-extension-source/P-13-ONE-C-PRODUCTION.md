# Подключение боевой 1С к СТО — действия специалиста 1С

## 1. Подготовить

- Сделать резервную копию базы и настроек веб-публикации.
- Получить `AvtoPult.cfe`, идентификаторы станций СТО и имена используемых профилей проведения.
- Проверить совместимость: КА2 Казахстан 2.4.5.21, платформа 1С 8.3.23.2040.

## 2. Установить расширение

1. Открыть «НСИ и администрирование → Печатные формы, отчёты и обработки → Расширения».
2. Нажать «Добавить из файла» и выбрать `AvtoPult.cfe`. Для обновления использовать
   «Обновить из файла».
3. Перезапустить сеанс и проверить, что расширение подключено без ошибок.

## 3. Создать профиль каждой станции

Выбрать существующий заказ с нужными организацией, подразделением, соглашением, валютой,
складом, видом цены и правилами расчётов. Выбрать строку услуги без НДС.

В консоли серверного кода выполнить:

```bsl
Источник = AvtoPultНастройкаПрофилей.НайтиДокумент(
    "ЗаказКлиента", "НОМЕР-ЗАКАЗА", 2026);

Результат = AvtoPultНастройкаПрофилей.СоздатьПрофильСтанции(
    "STATION-ID", Источник, 1);
```

Заменить номер, год, `STATION-ID` и номер строки. Функция сама создаёт отдельный
непроведённый технический заказ, переносит только настройки, обнуляет суммы и сохраняет
профиль. Повтор не создаёт дубль; повтор с другими настройками отклоняется.

Открыть `Результат.template`, проверить реквизиты и отсутствие проведения. После успешной
нативной проверки установить в `AvtoPultПрофилиСтанций`:

- `Проверен = Истина`;
- `БезНДСПодтверждено = Истина` — только для проверенного сценария без НДС.

## 4. Создать профили проведения

Для каждого сценария выбрать существующий проведённый документ нужного вида и операции.
Пример для наличной оплаты:

```bsl
Источник = AvtoPultНастройкаПрофилей.НайтиДокумент(
    "ПриходныйКассовыйОрдер", "НОМЕР-ПКО", 2026);

Результат = AvtoPultНастройкаПрофилей.СоздатьПрофильПроведения(
    "cash-receipt-v1", Источник);
```

Повторить для используемых заказов, счетов, безналичных оплат и возвратов. Функция сама
определяет тип документа и регистры движений, сохраняет их состав и хеш, не создаёт дубли
и отклоняет изменившийся состав движений.

После нативной проверки заполнить в `AvtoPultПрофилиПроведения`:

- `Проверен = Истина`;
- `ПроверенВ = ТекущаяДата()`.

## 5. Заполнить связи 1С

- `AvtoPultКлиенты`: идентификатор клиента СТО → партнёр и контрагент 1С.
- `AvtoPultАвтомобили`: идентификатор автомобиля СТО → автомобиль 1С.
- Проверить кассу, банковский счёт, валюту, соглашение, склад, налогообложение и печатную
  форму счёта.

## 6. Включить веб-обмен

1. В Конфигураторе открыть «Администрирование → Публикация на веб-сервере».
2. Открыть существующую боевую публикацию, включить OData и HTTP-сервис `AvtoPult`.
3. Сохранить публикацию, не меняя её адрес и остальные сервисы.
4. Создать пользователя чтения справочников и пользователя записи с правами расширения.
5. Проверить, что оба адреса отвечают без `404`:

```text
GET <адрес-публикации>/odata/standard.odata/
GET <адрес-публикации>/hs/avtopult/v1/diagnostics
```

## 7. Провести нативную приёмку

На копии боевой базы выполнить:

1. Создать профиль станции и повторить команду — один шаблон и один профиль.
2. Повторить с другим исходным заказом — конфликт без изменения профиля.
3. Создать профиль проведения и повторить — один профиль без дубля.
4. Заказ → изменение состава → проведение → проверка движений.
5. Счёт → штатный PDF → проверка номера, суммы и содержимого.
6. Частичная оплата → полная оплата → отмена → перепроведение без двойного учёта.
7. Возврат → повтор команды → один возврат и правильный итог.
8. Вызвать ошибку проведения — документ, движения, очередь и PDF полностью откатываются.
9. Оборвать связь после выполнения команды — повтор не создаёт документ или движение заново.

Сохранить протокол: версия платформы, КА2 и расширения, дата, база, номера документов и
результат каждого пункта.
